# Plan de Tareas: fetchmark-v3

## Resumen Ejecutivo del Plan

Este documento establece la secuencia atómica y detallada de tareas requeridas para el desarrollo, prueba y despliegue ONE SHOT en producción de **fetchmark-v3**.

El plan se organiza en 5 fases secuenciales strictly ordenadas:

- **Fase 0: Infraestructura y Enrutamiento Base**: Configuración de enrutamiento Vercel (`vercel.json`), árbol de rutas Angular (`app.routes.ts`) con vistas públicas (`/`) y privadas (`/dashboard`), e integración de guardias de navegación (`GuestGuard` y `AuthGuard`).
- **Fase 1: Serverless y Scraping Condicional**: Endpoint de scraping híbrido (`/api/bookmarks/scrape`) en `api/index.ts` con detección regex para URLs de YouTube, consulta a YouTube oEmbed API y fallback transparente a Cheerio.
- **Fase 2: Sistema de Diseño UI y Componentes Átomos**: Configuración de tema claro (Light Theme) por defecto en `src/styles.css` y `tailwind.config.ts`, desarrollo del menú Kebab táctil `BookmarkActionsMenuComponent` (`⋮`) accesible sin hover, y refactorización de tarjetas de marcadores.
- **Fase 3: Landing Page Pública**: Desarrollo del componente de Landing Page estática (`src/app/pages/landing/landing-page.component.ts`) con Hero Section, Features de scraping y botones de llamada a la acción (CTA) para inicio de sesión.
- **Fase 4: Dashboard y Ensamblaje Privado**: Rediseño del panel de control `DashboardPageComponent` con 1 solo botón primario en Header ("+ Nuevo Marcador"), icono minimalista `+` en Sidebar para carpetas, rejilla fluida de marcadores con skeletons y verificación end-to-end.
